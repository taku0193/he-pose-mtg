# 同じGPUでの順次計測と比較動画（2026-11-05）

`benchmark` は元動画を検証し、全モデルで推定できる元フレーム番号から共通のウォームアップと本計測を選びます。モデルごとのPython環境を順番に起動し、同じ割当GPU UUIDを使ったことを検証します。計測範囲の外も処理し、各モデルのサブディレクトリに全編の6出力を保存します。共通の集計は `benchmark.csv`、`report.md`、`environment.json` です。

`compare` は元動画のSHA256と各結果のrun_id・モデル・フレーム番号・時刻を照合し、同じ元画像の上に3結果を並べます。同じモデルの候補が複数ある場合や、別素材の結果が混ざる場合は失敗します。TARの前後2枚は `NOT ESTIMATED`、処理失敗や欠落も明示します。モデル重みやGPUは比較動画の生成に不要です。

実装は `src/hepose/benchmark.py`、`measurement.py`、`compare.py`、共通CLI・動画パイプラインです。モデルなしのRed→Greenは `work/tdd/30-benchmark-compare-red.log` と `31-benchmark-compare-green.log`。107件＋11 subtests、ruff、CLI helpを確認しました。テストでは共通フレームの選択、欠測の保持、別GPU割当の拒否、元フレームとTARの境界、重複モデル・不正なrun_id・異なる元動画の拒否、途中失敗時の比較を確認しました。

## abertでの実測

[利用条件を確認した運動動画](../../assets/sample/jumping-jacks-ATTRIBUTION.md)は640×480、25 FPS、375枚です。同じabertのRTX 3090（cuda:0）で、YOLO26→DETRPose→TARの順に別プロセスで処理しました。コミット `4ed899a`、未コミット変更なし。元フレーム2〜21を共通ウォームアップ、22〜121を本計測とし、各モデル1パスで反復なしです。単フレームモデルは全編保存のため元フレーム0・1も先に処理しますが、共通ウォームアップと本計測には含めません。

| 単フレームモデル | 処理FPS | 推論 p50 (ms) | 推論 p95 (ms) | 本計測 / 推論時間の有効件数 |
| --- | ---: | ---: | ---: | ---: |
| YOLO26n-Pose | 178.00 | 3.03 | 3.10 | 100 / 100 |
| DETRPose-N | 66.51 | 6.60 | 6.69 | 100 / 100 |

TAR-ViTPoseは前後2枚とYOLO11x検出器を使うオフライン処理で、20.36処理FPSでした。100枚中23枚では人物が検出されず、TAR本体のforwardがなかったため、推論時間は77枚分でp50 35.84 ms、p95 36.34 msです。処理FPSは復号、推定、描画、フレーム単位の書込を含む本計測区間の実経過時間から計算しています。TARでは検出器・クロップも含みます。推論時間はモデルforwardの別指標です。

比較動画は15秒、25 FPS、375枚、1920×528。全モデルのJSONL/CSVが元フレーム0〜374を保持し、TARだけ0・1・373・374が未推定であることを確認しました。比較画面の先頭・途中・末尾も確認済みです。短い入力の別試験では30枚を全て保存し、共通ウォームアップ後の10件を `insufficient_samples` と記録して終了コード1を返しました。

[機械可読の実験記録](../experiments/benchmark-abert-2026-11-05.json)、abertの出力は `outputs/benchmark-abert-2026-11-05`。実行・Macへの持ち帰り方は[README](../../README.md#3モデルを計測して比較動画を作る)を参照してください。GTがないため精度はN/Aです。この数値は1台・1素材での実測で、別環境の性能保証や遠隔ライブの表示FPSには使えません。次はMTGガイドと素材の準備、Mac実機と参加者3人の受入です。
