# HE研究室 人体姿勢推定ハンズオン

**90分 · 3人 · MacとLinux GPU**

2026年11月5日版

## 1. 今日の到達点

同じ動きを3モデルで見比べ、**どこまでの処理を何msで測ったか**と、**どの元フレームで骨格が揺れたり欠けたりしたか**を説明します。最後に、各自がHE研究で試したい用途を1つと、その効果を確かめる仮説を1つ持ち帰ります。

- 動作フィードバックでは、手が上がったことを知らせるまでの遅延と、腕を下ろしたときの誤通知を分けて考えます。
- 運動の反復を数えるなら、手首の上下を何フレーム連続で確認すれば、揺れによる二重カウントを抑えられるかを考えます。
- 二人で動く場面では、重なった後に二人分の骨格が戻るまで何フレームかかるかを記録します。

### 90分の進行

| 時間 | 全員で行うこと | その場で残すもの |
| --- | --- | --- |
| 0–20分 | 3モデルの入力と出力、処理FPS・推論時間・表示遅延を確認 | 何を比較するかを一言で説明 |
| 20–40分 | 各MacからYOLO26ライブを起動。腕上げと速い動きを試す | 表示FPS、アプリ内遅延、置換数、終了方法 |
| 40–60分 | 各自のGPUで同じ `basic.mp4` をYOLO26とDETRPoseで処理 | 同じ元フレームを2モデルで観察 |
| 60–75分 | 代表環境でTARを説明し、3モデル比較動画を再生 | 前後2枚の扱いと、遮蔽区間の観察 |
| 75–85分 | 環境別の数字と観察を記録 | 条件、フレーム番号、判定、成果物の場所 |
| 85–90分 | 各自1分で応用案と次回仮説を共有 | 指標、比較条件、次に収集するデータ |

進行役・時刻係・記録係を3人で分担します。ライブと録画推論は3人とも自分の端末で操作します。開催前に機材確認を終え、当日は実験と観察に90分を使います。

## 2. モデルと測定の読み方

| モデル | このデモでの処理 | 観察すること |
| --- | --- | --- |
| YOLO26n-Pose | 1枚から人物とCOCO17関節を推定。録画と遠隔ライブで使用 | 速い腕の切り返し、検出の途切れ、ライブ表示の反応 |
| DETRPose-N | 1枚をTransformer系の姿勢推定器に渡し、COCO17関節を得る | 同じ元フレームで人物数と関節の位置を見る |
| TAR-ViTPose Base | YOLO11xで人物を検出し、中心と前後2枚を同じ人物領域で切り出して推定 | 遮蔽の前後と、参照が足りない冒頭・末尾の各2枚 |

TARは未来側の画像も参照するため、今回は録画で実演します。頭頂・頭下端のように定義が異なる関節はネイティブ定義を保持し、対応しないCOCOの目・耳は欠測として記録します。モデルの説明と採用版は参考資料にまとめています。

| 指標 | 何を測るか | 読む場所 |
| --- | --- | --- |
| モデル推論時間 | モデルforwardの時間。GPUの完了を考慮 | `benchmark.csv` の推論p50・p95 |
| 録画処理FPS | 測定区間の処理枚数 ÷ 経過秒。復号・推定・描画・フレーム単位の結果書込を含む | `benchmark.csv` の `processing_fps` |
| ライブ表示FPS | Macで表示した結果の数 ÷ 観測秒 | Macの表示画面と `summary.json` |
| ライブのアプリ内遅延 | Macで画像取得直後から描画結果を表示APIに渡すまで | `display_latency_ms` のp50・p95 |
| 推定の観察 | 同じ時刻の揺れ、関節の欠落、左右の取り違え、遮蔽後の復帰 | 比較動画と元フレーム番号 |

アプリ内遅延はMacの単調時計で測ります。カメラの露光や画面の発光までを測るには別の計測が必要です。正解関節を付けていない素材では精度の欄を **N/A（GTなし）** と記録します。表示・処理・推論の各指標には、測定した環境と範囲を添えます。

## 3. 開催前の準備

```text
Macで取得した画像 → JPEGとフレーム番号 → SSH → LinuxのRTX 3090
Macで骨格を重ねて表示 ← 同じ番号の結果 ← SSH ← YOLO26
```

Linuxの各割当GPU、GPU UUID、既存のSSH接続先、両端のコミットを参加者ごとに確認します。モデルごとのPython環境とローカル重みを事前に用意し、`hepose.local.toml` に割当を設定します。MacはGUI版OpenCVを使い、起動するターミナルにカメラの使用を許可します。セットアップはREADMEのモデル別手順を使います。 [環境・重み・ライセンス](references.md)

| 素材 | 長さ / フレーム数 | 観察すること |
| --- | ---: | --- |
| `basic.mp4` | 12秒 / 300 | スクワットに合わせてゆっくり前へ上げる腕。肩・肘・手首の連続性 |
| `fast.mp4` | 15秒 / 375 | ジャンピングジャックとバーピー。速い切り返しや床へ手をつくときの欠落 |
| `multi.mp4` | 12秒 / 300 | 二人のサルサ。5〜8秒付近の交差と遮蔽、その直後の復帰 |

全素材は640×480、25 FPS、音声なしです。各Macの手元にガイド、比較MP4、計測表、素材のクレジットを置いて、一度開きます。参加者ごとの動作記録は事前に記入します。 [素材とSHA256](sample-sources.md) · [3人分の受入記録](acceptance.md)

## 4. 実演台本

`ssh abert` で接続済みのタブを開いたまま、第3節の準備を済ませておきます。当日はこの2つのタブを使います。

| タブ | 行う操作 |
| --- | --- |
| **abert**（SSH接続済み） | 録画の推論と計測、比較動画の生成 |
| **Mac**（SSHに入っていない別タブ） | カメラのライブ表示、結果のコピーと再生 |

abert側だけで先に試す場合は、40–60分の録画処理から始められます。別のLinuxを割り当てられた参加者は、接続名とリポジトリの場所を各自の環境に置き換えます。

### 0–20分　見るポイントを決める

進行役は「腕を上げてから、骨格が画面に出るまでのどこに時間がかかるか」と尋ねます。第2節の表を使い、モデルの計算時間、録画を処理する速さ、Macの画面に返るまでの時間を確認します。

### 20–40分　Macでカメラの骨格表示を試す

**Macの別タブ**で、Mac側のリポジトリへ移動します。ホームに置いた場合は `cd ~/he-pose-mtg` です。次のコマンドは、Macから `ssh abert` で接続できるSSH設定を使います。

```bash
.venv/bin/python -m hepose.cli doctor --role client &&
.venv/bin/python -m hepose.cli live --model yolo26 --camera 0 \
  --remote abert --remote-root /home/taku/he-pose-mtg --show-fps
```

`live` がMacからabertへのSSH接続を開き、abertで推論します。Macにカメラ画面が出たら、腕をゆっくり上げ、次に同じ動きを速く繰り返します。骨格が腕についてくるかを見て、画面で `q` を押します。Macのターミナルに戻ったら、表示されたログの出力先を控えます。Ctrl+Cなどの事前確認は別のセッションで行います。 [受入記録](acceptance.md)

### 40–60分　録画を処理し、Macで比較動画を開く

#### 1. 接続済みのabertでYOLO26とDETRPoseを順に実行する

**abertのタブ**へ切り替え、次のコマンドを実行します。GPUは事前に `hepose.local.toml` に記入した各モデルの `device` と `gpu_uuid` で選びます。

```bash
cd /home/taku/he-pose-mtg &&
root="outputs/mtg-basic-$(date +%Y%m%d-%H%M%S)" &&
.venv/bin/python -m hepose.cli benchmark --models yolo26,detrpose \
  --input assets/sample/basic.mp4 --output "$root" &&
.venv/bin/python -m hepose.cli compare --input-dir "$root" \
  --output "$root/comparison.mp4" &&
printf '%s\n' "$root"
```

成功すると最後に `outputs/mtg-basic-20261105-175336` のような行が出ます。**自分の実行で表示されたフォルダ名**を控え、Macの別タブへ切り替えます。abertのタブは開いたまま使えます。途中でエラーが出たら、端末の表示と、出力先に作られた `summary.json`・`run.log` を確認します。

#### 2. Macへコピーして再生する

**Macの別タブ**で、`run_name` の値を先ほど控えたフォルダ名に置き換えます。先頭の `outputs/` を除いた `mtg-basic-...` の部分を使います。

```bash
run_name=mtg-basic-YYYYMMDD-HHMMSS
mkdir -p outputs &&
scp -r "abert:/home/taku/he-pose-mtg/outputs/$run_name" outputs/ &&
open "outputs/$run_name/comparison.mp4"
```

腕が前へ伸びるところで動画を止め、左右のパネルに表示された同じ元フレーム番号で、肩・肘・手首を見比べます。コピーしたフォルダには比較動画と計測表、両モデルの実行記録が入っています。 [当日のコマンド表](commands.md)

### 60–75分　進行役がTARの録画結果を見せる

配布セットの `results/multi/comparison.mp4` をMacで開きます。左からYOLO26、DETRPose、TARです。

1. 冒頭のTARパネルで `NOT ESTIMATED` を見ます。TARは前後2枚を必要とするので、最初に推定できる元フレームは2です。このフレームは0〜4を参照します。対応は `results/multi/tar-poses.jsonl` に記録されています。
2. 二人が重なる5.40秒（元フレーム135）と、その後の6.00秒（フレーム150）で止めます。保存結果の検出人数は、左から順に **1・1・2人** と **2・2・3人** です。画面奥の人も映っているので、人数に加えて骨格がどこに出たかを見ます。

`NO PERSON` は推定した結果が0人、`NOT ESTIMATED` は推定していないフレームです。`FAILED` や `NO SAVED RESULT` が出た場合は、失敗や保存結果の欠落として記録します。

進行役が再実行する場合は、準備済みのabertのタブでリポジトリ直下に移動して実行します。

```bash
.venv/bin/python -m hepose.cli run --model tar-vitpose \
  --input assets/sample/multi.mp4 --output "outputs/tar-mtg-$(date +%Y%m%d-%H%M%S)"
```

### 75–90分　見つけたことを共有する

75–85分で、各自が素材名、元フレーム番号、モデル、見え方を1件記録します。85–90分で、その観察から考えたHEへの応用案と、次に何を測るかを1人ずつ共有します。 [観察・仮説の記入欄](observations.md)

### 当日の切替

| 起きたこと | 次に行うこと | 記録する判定 |
| --- | --- | --- |
| カメラが開けない、SSHはつながる | Linuxで `basic.mp4` を処理してMacで再生 | 録画推論の結果とライブの失敗を別に記録 |
| SSHまで切れる | 事前保存した比較MP4、計測表、録画再送の結果をMacで開く | 保存済み結果による代替と記録 |
| 代表のTARが起動しない | abertで取得済みのTARパネルを再生 | 生成環境と当日の起動失敗を記録 |
| 動画のプレーヤーが対応しない | 配布フォルダのH.264版 `comparison.mp4` を使う | 使用したファイルを記録 |

## 5. abertで測った結果

`fast.mp4` は前回検証した素材と同じファイルです。abertのRTX 3090で、FP32、batch=1、同じ元フレーム2〜21をウォームアップ、22〜121を本計測としました。モデル別に別プロセスで順番に処理しています。

| 単フレームモデル | 処理FPS | 推論p50 | 推論p95 | 測定 |
| --- | ---: | ---: | ---: | ---: |
| YOLO26n-Pose | 178.00 | 3.03 ms | 3.10 ms | 100件 |
| DETRPose-N | 66.51 | 6.60 ms | 6.69 ms | 100件 |

**TAR-ViTPoseのオフライン測定**では20.36処理FPSでした。処理100件中、人物が検出された77件のTAR本体の推論時間はp50 35.84 ms、p95 36.34 msでした。処理FPSにはYOLO11xでの人物検出とクロップ処理も含みます。

比較動画は3つのモデルを左からYOLO26、DETRPose、TARの順に表示します。たとえば `fast` の元フレーム374では、YOLO26は0人、DETRPoseは人物を推定し、TARは時間窓の境界で未推定でした。各ラベルが示す処理状態の違いを、同じ元画像で確認できます。 [実測条件と集計](../pr-notes/benchmark.md)

`basic` と `multi` でも、3モデルを同じ100件で順次測定し、各300フレームを揃えた比較動画を作りました。素材別の `benchmark.csv` と比較MP4を配布フォルダで確認できます。 [3素材の実行記録](../experiments/mtg-abert-2026-11-05.json)

### ライブの準備状況

abertでのSSH録画再送では375枚中369枚に結果が返り、待機中の6枚が置き換わりました。切断・Ctrl+C・期限切れでのワーカー終了を確認済みです。Mac実機のカメラ、表示遅延、参加者3人の受入は当日までに個別に確認します。 [SSH録画再送の検証記録](../pr-notes/remote-live.md)

## 6. 制限と参考資料

実測値は同じabertと各素材での結果です。参加者ごとのGPU、Mac、ネットワーク条件は環境別に記録します。正解関節が必要な検証では、観察した区間にアノテーションを作り、評価方法を先に決めます。公式資料に掲載された速度を引用する場合は、GPU、入力、実行エンジンなどの測定条件も添えます。
